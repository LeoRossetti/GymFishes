### Task 1: Accessibility — contrast scoping, targets, focus, disabled state, screen-reader parity

**Files:** `src/app/TabBar.tsx`, `src/ui/Button.tsx`, `src/styles/globals.css`, `src/screens/hoje/EntryRow.tsx`, `src/screens/hoje/Hoje.tsx`, `src/screens/registrar/BottleGrid.tsx`, `src/features/fish/FishGrid.tsx` (+ test), `src/screens/onboarding/Onboarding.tsx`, `src/screens/historico/CalendarGrid.tsx` (+ test), `src/screens/auth/Login.tsx`, `src/screens/auth/SignUp.tsx`, `src/screens/perfil/Perfil.tsx`, `src/lib/strings.ts`, and the existing tests of any component whose text or roles change.

Read the accessibility skill first. Then:

- [ ] **#1 — `--ink-3` carries no content.** Wherever `text-ink-3` is used for content a user must read, switch to `text-ink-2`: the composition/note line under a register (`EntryRow.tsx` ~63), inactive tab labels (`TabBar.tsx` ~10), the date under "Hoje" (`Hoje.tsx` ~23), bottle volumes in the register grid (`BottleGrid.tsx` ~42), the fish unlock condition (`FishGrid.tsx` ~38) and any equivalent in `Onboarding.tsx` (~184). Section labels (9px uppercase) and disabled states keep `text-ink-3` — that is spec §8's scope for the token. Do not change the token value.
- [ ] **#2 — Tab bar targets.** Each `NavLink` in `TabBar.tsx` gets `min-h-[44px]` with its content vertically centred; move the bar's top padding into the link so the whole 44px is tappable. The central "+" already meets the floor.
- [ ] **#3 — Disabled and busy buttons are legible.** In `Button.tsx` replace `disabled:opacity-40` with a flat disabled treatment that stays readable: for `primary`, `disabled:bg-surface-2 disabled:text-ink-2 disabled:border-line disabled:border-b disabled:translate-y-0` (no active press while disabled); for `ghost`/`danger` keep the surface and drop to `disabled:text-ink-3`. Add `aria-busy` where a button is disabled *because* an async action is running: Login ("Entrar" → label `STRINGS.auth.entrando` while busy), SignUp (`STRINGS.auth.criandoConta`), Onboarding "Continuar" (`STRINGS.onboarding.salvando`) and Perfil "Salvar" (`STRINGS.perfil.salvando`). New strings: `auth.entrando: 'Entrando…'`, `auth.criandoConta: 'Criando conta…'`, `onboarding.salvando: 'Salvando…'`, `perfil.salvando: 'Salvando…'`. Test (Login.test.tsx): while the sign-in promise is pending the button reads "Entrando…" and has `aria-busy="true"`.
- [ ] **#6 — Global focus ring.** In `globals.css`: `:focus-visible { outline: 2px solid var(--color-water); outline-offset: 2px; }` and remove `outline-none` from `Field.tsx` if it suppresses this (keep the `focus:border-water` look).
- [ ] **#7 — The calendar says the total.** In `CalendarGrid.tsx` the day button's `aria-label` becomes `STRINGS.historico.diaComTotal(formatDayLong(day), total > 0 ? formatVolume(total) : STRINGS.historico.semRegistro)`. New strings: `historico.diaComTotal: (dia: string, total: string) => \`${dia} · ${total}\``, `historico.semRegistro: 'sem registro'`. Test first: a 3 L day is named "segunda, 3 de agosto · 3 L"; an empty day "… · sem registro".
- [ ] **#8 — Calendar text crossover.** Day numbers use `text-ink` on fill steps 0–3 (none, `/25`, `/50`, `/75`) and `text-ink-on-water` only on step 4 (full `bg-water`). Check `src/lib/calendar.ts` for how steps map to classes and keep the mapping in one place.
- [ ] **#11 — Locked fish stay reachable.** In `FishGrid.tsx` a locked cell is `aria-disabled="true"` with a handler that does nothing (not `disabled`), so VoiceOver can read its condition; `disabled` remains only for the `disabled` prop (busy). Condition label `text-ink-2`. Update `FishGrid.test.tsx`: locked cell has `aria-disabled="true"`, clicking it does not call `onSelect`; the Perfil and Onboarding tests that used `toBeDisabled()` on a locked fish assert `aria-disabled` instead.
- [ ] **#22 — The failure dot tells the truth.** In `EntryRow.tsx` the dot's `aria-label` is `STRINGS.sync.falhou` when `failed`, `STRINGS.sync.pendente` otherwise. New string `sync.falhou: 'Falha ao enviar'`. Test in `EntryRow.test.tsx`.
- [ ] Run `npm run test:run && npm run typecheck`; commit `fix(a11y): contrast scoping, 44px tabs, legible disabled state, focus ring, calendar and fish announcements`.

### Task 4: The register sheet and dialogs — gesture conflict, modal semantics, announced celebrations

**Files:** `src/screens/registrar/RegisterSheet.tsx` (+ test), `src/features/celebrations/CelebrationScreen.tsx` (+ test), `src/lib/strings.ts`.

- [ ] **#4 — Swipe-to-dismiss lives on the handle.** `motion`'s `drag="y"` on the scrolling sheet element claims vertical touch gestures, so a sheet taller than the viewport (3+ bottles, or the nota/hora field open) cannot be scrolled on a phone and a scroll gesture can dismiss it. Use `useDragControls()`: the sheet keeps `drag="y"` but gets `dragListener={false}` and `dragControls={controls}`; the grab handle (`div.mx-auto.mb-3.h-1.w-10…`) becomes a `min-h-[44px]` touch area (keep the 1×10 bar visually centred inside it) with `onPointerDown={(e) => controls.start(e)}` and `touch-action: none`. Backdrop tap still closes. Test: the handle has an accessible name `STRINGS.registrar.arrastarParaFechar` (new: `'Arraste para fechar'`) and the sheet content still scrolls (`overflow-y-auto` present on the sheet, `drag` not listening on it — assert via the handle existing and the existing submit tests staying green).
- [ ] **#9 — Dialogs behave like dialogs.** Both `RegisterSheet` (`role="dialog"`) and `CelebrationScreen` get `aria-modal="true"`. `CelebrationScreen` also moves focus to itself on mount (`tabIndex={-1}` + `ref.current?.focus()`) and renders a visually hidden `<p role="status">` with `celebrationText(celebration)` so VoiceOver announces what sighted users see (the Toast already proves the pattern). Test: on mount the dialog is `document.activeElement` and a `status` element contains the celebration text.
- [ ] Run tests + typecheck; commit `fix(sheet): drag on the handle only; modal semantics and announced celebrations`.
